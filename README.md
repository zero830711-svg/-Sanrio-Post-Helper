# Sanrio Post Helper

**Current app: 2026.09.24-3323**

iPhone中心で、過去のX投稿を分析・再利用するためのWebツールです。

## 主な機能
- Codex確認用の期限付き閲覧リンク（今日の候補5件、30分）。候補の役割と選定理由も表示（共有APIの変更や手動アップロードは不要）
- XアナリティクスCSVの一括取り込み
- Amazon紹介レポートZIPを複数アカウント・期間別に自動合算し、紹介料・発送売上・クリック・発送商品と商品実績を表示（端末内保存）
- 楽天注文別Excelを月別に取り込み、楽天レポート全体の確定／未確定報酬を端末内で確認。商品名・ショップ名はサンリオ関連と確認できる明細のみ表示し、別商品購入分をサンリオ商品売上と誤認しない（計測ID入力不要）
- Trend Radar：Sanrio公式、Google News系の公開RSS、Reddit公開情報から国内外の最新話題を取得
- 72時間以内を中心に表示し、7日超の古い話題は除外
- 同じニュースをタイトル類似度でまとめ、関連媒体数を表示して重複カードを削減
- 公式・国内記事・商品/コラボ/限定/新作を優先し、ゲーム/企業ニュースは順位を抑制
- トレンドの鮮度・複数媒体確認・Reddit反応・自分の過去キャラ別CTRを組み合わせて「今乗るネタ」を上位表示
- 各話題に「今すぐ投稿 / 投稿候補 / 先取り候補 / 様子見」のチャンス判定を表示
- 海外で出ているのに日本語ニュースがまだ見当たらない話題を「先取り候補」として強調
- 各トレンドに、自分の過去データから関連キャラ・キーワードが近く実績の強い投稿を最大2件表示
- 各トレンドからChatGPT/Gemini用のX投稿プロンプトをワンタップコピー
- 「今日の新規ネタ」を1件だけトップ表示し、Trend Radar本体は折りたたみ
- Trend Radarは24時間 / 72時間 / 7日を切替
- 「投稿した / 今回は使わない / 興味なし」をサーバー保存し、同じネタの再表示を防止
- 新商品 / コラボ / 限定 / 再販 / イベント / 海外先行を自動分類
- 情報源を「公式確認 / 複数媒体確認 / SNS情報」などで信頼度表示
- 関連媒体のリンクをまとめて確認可能
- 曜日・時間帯ごとの平均表示・CTRを分析
- 直近21日の似た文章・キャラ偏りを「焼き直し注意」として表示
- Trend APIは今後 `trend.php` 1本を上書き更新する方式に固定
- 表示数・いいね・保存数・URLクリック数の保存
- 30日以上あけた投稿から「拡散狙い / クリック狙い / 鉄板再利用」の3つの固定席で今日の候補を選定
- 候補に表示しただけでは7日休みにせず、見送った投稿だけ7日休ませる
- 表示・保存・クリック・リポストを合わせた「今日の爆発候補」を1件選定し、表示後7日休ませる
- 「見送る」で再投稿扱いにせず7日休ませる
- URLだけ・極端な短文は今日の候補と分析ランキングから自動除外
- 「候補にしない」は状態＋更新日時で管理し、古いバックアップ読込でも復帰状態を保護
- 「自動除外」フィルターでURLだけ・短文投稿と除外理由を確認可能
- 選定理由を表示し、役割に必要な指標だけを候補カードへ表示
- トップに「今日の再投稿件数 / 見送り件数」を表示
- 直近7日で再投稿した「今週使った投稿」を表示
- 古い可能性のある速報・日付入り投稿を一覧で確認
- キティ / クロミ / マイメロ / シナモン（シナモロール含む） / プリン / ポチャッコのワンタップ検索
- Amazon / 楽天 / アフィリエイト投稿の絞り込み
- 表示・いいね・保存・クリック順の並び替え
- X投稿文のコピー、元投稿表示、再投稿履歴管理、5秒間の取り消し
- 過去投稿一覧は普段は折りたたみ、50件ずつ追加表示してiPhone負荷を軽減
- FlexSearch（Apache-2.0）を使った高速全文検索
- Chart.js（MIT）を使った端末内分析ダッシュボード
- 表示1,000以上を対象に、クリック率・保存率TOP5をスマホ向けランキング表示し、X表示・コピー・候補除外・空き枠への候補追加を直接操作
- 新作・再販・限定・予約・価格訴求・Amazon・楽天・まとめ等の投稿文パターンごとに平均表示・CTR・拡散率・保存率を比較
- キャラ別平均クリック率を対象投稿件数つきでグラフ表示
- 最新投稿の日付・登録件数・最終CSV読込時刻をトップに表示
- version.json を使って起動時に最新版を自動検知し、「最新版を読み込む」ボタンで更新
- データ健康診断で重複・Xリンクなし・自動除外・古い可能性・候補除外を集計してワンタップ確認
- 同じX postId / status ID の重複データを履歴・画像・指標を保ちながら統合
- 最終バックアップ日時を表示し、10日以上経過で警告
- CSV・バックアップはIndexedDBへ一括保存して高速化
- JSONバックアップ／復元
- Xアーカイブの一括取り込み：既存データは保持し、同じpost IDを補完
- Xアーカイブの写真・動画をロリポップのファイル領域へ保存
- メディアURLを投稿データにも同期し、別端末でも過去画像を表示
- 中断したメディアアップロードは完了済みバッチを飛ばして再開
- 3020では取り込み済みアーカイブのメディアを一度再照合し、抜けた画像・動画を補完（同一post ID＋SHA-256は重複保存しない）
- 管理画面で投稿DB件数・写真枚数・動画本数・使用容量を確認
- メディア台帳から画像リンクを再構築する機能
- クラウド統合のたびに画像・動画リンクを自動再チェック

- Threads用プロンプトでは元のX本文からURLを抽出して候補を明示し、短縮URLの行き先と商品一致が確認できたときだけ返信リンクを作る
- 投稿詳細の「ブログ用プロンプトをコピー」の下に「Threads用プロンプトをコピー」を配置。親投稿と、確認済み商品リンクがある場合だけ返信文を別々のコードブロックで生成
- 収益改善候補：高表示・低クリック率のアフィリエイト投稿を抽出し、事実確認ルール付き改善プロンプトをコピー
- X投稿のクリック改善とリンク経由の収益を分けて表示。Amazonは主アカウントの最新レポートだけを集計して期間重複を避け、楽天は確定・未確定を分ける。購入された商品名からX投稿案は作らない

## 保存方針
データは端末内のIndexedDBに保存します。GitHubには投稿データを保存しません。


## ロリポップ同期（任意）

GitHub Pages の画面はそのまま使い、投稿データだけをロリポップの PHP + MySQL に保存できます。

- Xアーカイブ由来の写真・動画はロリポップのファイル領域へ保存し、投稿データにはそのURLを同期します。
- API URL と同期キーは端末の localStorage に保存し、GitHub リポジトリには保存しません。
- 初回設定後は起動時にロリポップから自動統合します。
- 再投稿済み・見送り・候補除外・CSV読込などは数秒後に差分だけ自動保存します。
- 削除と重複統合も削除情報（tombstone）として同期し、別端末で古い投稿が復活しにくい構成です。
- 手動の「クラウドへ保存」「クラウドから統合」も残しています。
- 端末内画像も保持できますが、ロリポップ上のクラウド画像URLを優先して別端末でも表示できます。
- サーバー側のサンプルは `server/lolipop/` にあります。

### セットアップ概要

1. ロリポップで専用 MySQL データベースまたは専用テーブルを用意
2. `server/lolipop/schema.sql` を phpMyAdmin で実行
3. `config.example.php` を `config.php` にコピーして DB 情報と長い同期キーを設定
4. `api2580.php`、`trend.php`、`archive-media-batch.php` と `config.php` をロリポップの公開ディレクトリへ配置
5. アプリの「管理 → ロリポップ同期」で同期キーを入力して「接続確認」
   - API URL は `https://fan-info.zombie.jp/sanrio-fan/sanrio-sync/api2580.php` を初期値として設定済み

**重要:** `config.php` は GitHub にアップロードしないでください。
