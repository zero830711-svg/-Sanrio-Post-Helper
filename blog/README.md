# 商品記事を増やす手順

## 商品カタログを増やす（記事を作らない同期）

数千件を目指す商品一覧は、商品記事とは分けて管理します。商品データを `blog/products-*.json` に追加すると、GitHub Actions が標準WordPress REST APIで `/goods/` と関連キャラクター導線を更新します。**この同期では商品記事を作成・公開しません。**

- 各商品にキャラクター名・`character_slug`・カテゴリ・`kind_slug`・商品名・検索語を持たせます。識別子はJANを優先し、JANがない商品はAmazon ASIN、楽天商品コード、`catalog_id`で扱い、同じ識別子の重複を除きます。
- 同じJANは重複登録しないようにします。公開記事がある商品は詳細記事へのリンクを表示し、記事がない商品も一覧カードとAmazon・楽天市場の検索リンクで掲載できます。
- 商品画像はWordPress内で確認できた画像だけ表示します。未記事の商品には画像プレースホルダーを使います。
- 価格・在庫を固定掲載せず、購入先で最新情報を確認する導線にします。
- Post Helperの「Amazon API接続」では、検索結果をチェックし、キャラクターとジャンルを指定して「選択した候補をJSON保存」します。楽天の商品確認画面では「商品カタログ候補を書き出す」から1件ずつ保存できます。どちらも記事は作成しません。
- ダウンロードしたJSONを確認し、Amazonの商品とキャラクターの一致、楽天のJAN・商品コード、タイトル、ジャンルを確認してから `blog/products-*.json` の新しいバッチとして追加します。追加されたレビュー済みバッチはActionsが一覧を同期します。
- 記事の下書き・公開が必要な商品だけ、後述の `Sanrio WordPress REST` を手動実行します。

現在はレビュー済み20件を一覧へ反映済みです。今後はPost Helperや楽天/Amazonの検索候補から確認できた商品のデータを追加し、記事を増やしすぎずにカタログを広げます。

## 標準REST APIで記事を作る（必要な商品だけ・WPVibe不要）

## 標準REST APIでの登録（推奨・WPVibe不要）

WordPressのプロフィールでアプリケーションパスワードを作成し、GitHubの当リポジトリの Settings → Secrets and variables → Actions に次を保存します。値をチャット、ソースコード、リポジトリ変数に記載しないでください。

|Secret名|値|
|---|---|
|`SANRIO_WP_USER`|WordPressのログインユーザー名|
|`SANRIO_WP_APP_PASSWORD`|新規発行したアプリケーションパスワード（通常のログインパスワードは使用しない）|

Actions → **Sanrio WordPress REST** → Run workflow を開きます。

- `check`：認証・商品紹介カテゴリー・既存記事の重複を確認。書き込みなし。
- `draft`：重複のない商品を画像付きの下書きに登録。
- `publish`：下書きとアイキャッチの保存を検証してから公開。既存の公開記事は変更しません。正規スラッグの既存下書きは再開します。

対象は `blog/products-*.json` にあるレビュー済みデータです。記事の下書き・公開は手動実行です。画像はメーカーの確認済みURLから取得し、WordPressのメディアへ保存します。REST APIはサイトを `https://sanrio-fan.site` に固定し、認証ヘッダーの転送を伴うリダイレクトは拒否します。認証情報とサーバーのレスポンス本文はログへ出しません。

プラグイン設置は不要です。追加の定期実行は設定していません。`python3 -m unittest discover -s blog/tests -p test_wordpress_rest.py -v` で重複・再開・公開前検証を確認します。

## Post Helperの商品カタログJSON

カタログJSONはレビュー前の候補データです。商品とキャラクターの関連、ジャンル、識別子、検索語を確認してから `blog/products-*.json` に追加してください。商品の多くはカタログ一覧のみで運用し、記事が必要なものだけ標準REST APIのワークフローで作成します。

楽天商品の「ブログ用データを保存」は記事用JSONです。カタログへ追加する場合は新しい「カタログ候補JSONを保存」を使ってください。Amazon検索画面のJSONは複数候補を配列で保存し、そのままバッチ形式として確認できます。

## 過去の任意インポーター（現行フローでは未使用）

以前用意したWordPressプラグインによる記事取り込み手順は現行フローでは使用しません。WordPressへの商品記事作成・公開は、下記の `Sanrio WordPress REST` ワークフローのみを使います。

参考用にプラグインのコードは残っていますが、インストールや有効化は不要です。現行の登録は標準WordPress REST APIだけで行います。

`products-2026-10-18.json` は公式スケーター商品ページで仕様を確認した５件です。Amazon・楽天はJANを含む検索リンクと明記しています。価格・在庫・未確認の発売日は掲載していません。
